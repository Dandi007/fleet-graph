# M4 —— 「功能可用性」判定口：up == 0 之外的那一层

现有 118 条告警规则里 68 条基于 up == 0，没有一条问「这个服务的功能还能用吗」——ronin-mcp 38/59 工具坏掉却全绿的证据（wf-525fd4 goal.md M4）。本线只给「MCP 面怎么算可用」的**判定口**；告警规则的书写归 wf-6475fd（不要两边各写一套）。

## 交付物

1. 一个可调用的 MCP 面可用性判定口（函数/模块）：给定一个 MCP 面，判定其「功能可用」= 至少 `tools/list` 成功 **+** 一个只读工具的真调用成功。返回结构化「可用/不可用」结论 + 证据，而非 bool。
2. `tests/test_m4_availability.py`（本单验收目标，含独立 negative 用例）。

## 双向判据（不可弱，逐字对齐 goal.md M4）

- **阳性**：把某个 MCP 面的上游指向一个不存在的地址 → **必须**（判定口产出「不可用」，告警据此可开火）。
- **阴性（不许恒亮）**：面正常时不得开火（判定口产出「可用」）；且**显式声明为 NOT_SUPPORTED 的历史工具不得被算作失败**（dd 面就有 5 个这样的工具，它们返回拒绝是正确行为）。

## 红线纪律

- 判定口是纯判定：只给「可用/不可用」判定值与证据，不直接写告警规则（告警归 wf-6475fd）。
- 判据 = `tools/list` 成功 + 只读工具真调用 ≥ 1；NOT_SUPPORTED 工具的拒绝不计失败。
- 面不可达等「不可判定」情形须显式标注，不得静默断言成「可用」或「不可用」。
- 可无传输层单测（注入 fake 面），测试不触碰生产账本/生产文件。
- 不删除/改写既有测试或 scripts/；`make verify` 不回归（新增文件过 ruff/format）。
