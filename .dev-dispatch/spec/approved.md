# 验收脚手架 scripts/verify-mcp-only.sh（存在且诚实报红）

本开发单只做一件事：在 fleet-graph 仓库落地验收脚手架
`scripts/verify-mcp-only.sh`，使它「存在且诚实报红」。这是 wf-525fd4
「全舰入口收敛到 MCP」goal 的首轮第一件事（goal.md 的「首轮的第一件事」）。

## 背景约束（不许软化）

- 判据全红是 goal 线的正常起点；但「一个不存在的脚本不是判据」、
  「一个恒绿的脚本也不许有」。
- 该脚本是这条线唯一的验收入口。此后每交付一项 M，脚本增加对应一段、
  红转绿；全部交付后脚本返回 0（全绿）。此刻（M0–M4 均未交付）它必须返回
  非零并逐条列出未满足原因。

## 交付物

### scripts/verify-mcp-only.sh

一个可执行 bash 脚本（shebang `#!/usr/bin/env bash`，`set -u` 起步，
不依赖本仓库之外的私有工具；只许用 bash / git / curl / python3 / uv 等
本机已存在的通用命令）。脚本必须：

1. **逐条覆盖 M0/M1/M2(a)/M2(b)/M3/M4，且每条都含双向判据（阳性 + 阴性）。**
   判据内容以 wf-525fd4/goal.md 为准，逐字对齐，不许自创替代判据：

   - M0 阳性：经 MCP 能发出一条带 ref 的 `work.decision.v1`，且板上落地的 refs 与传入一致。
     M0 阴性：协议要求 ref 而调用方未给 → 必须在调用点报错，不许发出去再由下游 422。
   - M1 阳性：正在跑的线，MCP 工具返回的 generation/round/phase 与同刻 `:7494` 逐字段相等。
     M1 阴性：线状态面只读，不得暴露任何写能力（给一个写原语必须有用例变红）。
   - M2(a)：裁决工具能对「dd 闸」投递（不只认「哪条线」）。
   - M2(b) 阳性：对驻停等裁决的线投递 → 返回「已送达且被消费」，且该线在 N 个调度 tick 内点火。
     M2(b) 阴性：线未驻停 / 无此等待方 / 载荷非法 → 明确拒绝码，不得静默吞掉。
   - M3：每一个 ronin-mcp 工具要么可用、要么被显式标记退役（wf/fs 那 22 个是缺陷、应修）。
   - M4 阳性：把某 MCP 面的上游指向不存在地址 → 必须告警。
     M4 阴性：面正常时不得开火；显式 NOT_SUPPORTED 的历史工具不得算失败。

2. **诚实报红**：M0–M4 当前均未交付，脚本运行后必须**逐条打印**每条判据的
   未满足证据，并返回非零。每条红必须给出「具体证据」，例如：
   - M0 阳性红：指出 `agent-bus-mcp` 网关 `bus_publish` 工具入参 schema 缺 `refs`
     （可实际用 MCP `tools/list` 或网关源码佐证），或实发一条 `work.decision.v1`
     被下游 422 拒绝的具体回显。
   - M1 红：指出线上没有 line-state 的 MCP 工具（`:7494 /mcp` 404、`tools/list` 无对应工具）。
   - 依此类推，每条红必须是「探测到的现实」，不是一句空泛的「未实现」。

   判定红绿的探测必须真的去探（探网关 schema / 探 endpoint / 探源码），
   不许硬编码「红」或「绿」；探不到也要如实报「不可判定」并算红，同时给出
   「为什么不可判定」的证据（如「上游不可达：connection refused」）。

3. **红线纪律**：
   - 脚本里不得出现以 `No such file or directory` 充当一条判据的情况；
     「文件不存在」只能作为一种探测失败的证据，且必须落到对应判据那一行。
   - 不得有任何「恒定绿」的输出（不探就报绿）。
   - 退出码 = 红色判据的条数（至少 1，最多等于总判据条数）；全绿时才是 0。
   - 输出必须稳定、可重复执行（多次运行结果一致，不夹带随机量/时间戳以外的无意义差异）。

### tests/test_mcp_only_scaffold.py

一个 pytest 用例文件，用于把「脚手架诚实红」这套纪律固化成可回归的判据
（本开发单的验收命令即运行它）。它必须断言：

1. `scripts/verify-mcp-only.sh` 存在且可执行。
2. 以 `bash scripts/verify-mcp-only.sh` 在仓库根目录运行一次 → 返回码非零（当前必须红）。
3. 输出里**同时**出现 `M0`、`M1`、`M2`、`M3`、`M4` 五个标记。
4. 输出里出现 `阳性` 与 `阴性`（双向判据都覆盖）。
5. 输出非空，且不以「`No such file or directory`」作为对「脚本缺失」的替代
   （即：脚本确实被执行了、确实产出了逐条判据输出）。

测试必须自包含（用 subprocess 在仓库根目录跑那条命令），不依赖任何网络服务。

## 不许做

- 不许删除/改写任何既有测试或 `scripts/` 下既有脚本。
- 不许让 `make verify` 回归（新增文件须通过 ruff / format）。
